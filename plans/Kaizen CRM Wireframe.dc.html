A role change (Student → Alumni → Corporate Contact) never creates a new Person. A relationship change (Prospect → Training Partner → Technology Client) never creates a new Organization. Institutions are Organizations with institution_type set — same table, same relationship/activity/opportunity machinery.

CONTEXTUAL (tabs inside a record, not standalone)
Communications, Tasks, Notes, Documents, Payments, Timeline — always rendered as tabs on Person / Org / Institution / Opportunity, never a lone top-level page a user has to remember to visit. Activities top-nav item is a cross-record inbox (calendar + task list + comms) for "what do I do today," distinct from the per-record tab.
Why these calls
Institutions gets its own primary nav item (not buried under Organizations) because the map-based prospecting workflow (§10–14) is a flagship, high-frequency flow for counsellors and BD — it needs a one-click entry point. It's still an Organization subtype underneath.

MoUs is primary because the spec explicitly rejects "MoU = Yes/No" — it's a first-class record with its own lifecycle, list, and renewal workflow, used by both Institutions and corporate Organizations.

Communications is not primary. Reps live inside a record when they message someone; a standalone inbox is only useful as a triage view, so it's folded into the Activities hub instead of fragmenting attention across two navs.

Campaigns / Projects exist in the model (they're referenced by Opportunities and Leads) but are deferred to Phase 2 in this delivery — see Handoff Summary.
